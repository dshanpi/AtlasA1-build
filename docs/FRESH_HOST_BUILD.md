# 全新主机构建：交付条件与当前缺口

2026-11-23 的目标是：用户只需拉取 AtlasA1-build，在全新 Linux 主机执行一个入口，即可生成与当前实板相同的软件版本、板级配置和 GNOME/GPU/Cedar 功能的完整 eMMC 镜像。用户不再提供 Tina SDK、私有压缩包、旧构建目录或人工安装板级补丁。显示默认值和自动校时修复也应包含在镜像中。

**现有主分支尚未达到这个目标。** 四个源码仓库、单补丁及实板证据已经备份，但源码备份完整不等于从空白主机成功构建。现有 `build_atlasa1_resolute.sh` 仍要求 `ATLAS_TINA_SDK`，下面列出的缺口未验证解决前，不将它称为全新主机一键构建。

## 必须消除的依赖

| 当前输入 | 已发现的问题 | 完成交付的条件 |
| --- | --- | --- |
| DDR 训练库 | 启动源码外另需固定 SHA-256 的 `libdram` | 必需的闭源输入随版本管理，由入口自动获取和校验；用户不准备 SDK |
| Tina 显示、PowerVR 内核源码 | 内核重建导入 264 个显示文件及 Rogue KM 源码 | 将必要源码、版权说明和补丁固定存放到组件仓库或可下载源码附件，独立校验 |
| PowerVR 用户态和 Cedar 库 | 工具从 SDK 深层目录提取运行库 | 固定最小输入集及 SHA-256，自动下载；缺项时失败，不能省略 GPU/视频 |
| Cedar/OMX 编译 | `build_cedar_4k_omx.py` 复制配置后的 libcedarc 并复用旧对象；服务构建依赖 SDK sysroot | 从源码重新配置、编译，明确保留的厂家闭源库；不能依赖旧 `.o`、libtool 缓存或旧主机绝对路径 |
| 主机工具链 | GCC、ARM32/AArch64 工具链及 QEMU 由主机手工提供 | 固定构建环境、自动准备依赖，在隔离环境测试 |
| Ubuntu 软件包 | 当前 APT 安装跟随镜像站更新 | 固定版本清单及可取回的软件包校验和；对照当前系统，不静默升级 |
| 官方源码 | Armbian、内核、U-Boot、TF-A、FFmpeg 等分散下载 | 一个输入清单记录提交、来源及哈希，自动获取，支持缓存和失败重试 |

闭源 DDR/GPU/编解码组件仍是实现这些功能的必需部分；“不依赖其他”在工程交付中指不依赖用户另行寻找的 SDK、私有文件和当前构建机。不能声称这些闭源组件已被源码替代。

## 通过标准

1. 全新 Ubuntu 24.04 x86_64 验收环境，不挂载开发者 home、旧 Tina 或构建缓存。
2. 只允许版本化的公开源码、记录并校验的下载输入和标准构建环境；一次命令完成。
3. 编译日志证明内核、启动链和可编译的多媒体组件重新构建，不用现成系统镜像冒充编译结果。
4. 对比内核配置、启动参数、GNOME、GPU、播放器、Firefox、软件包版本和首次启动配置。
5. 输出完整 eMMC 镜像、SHA256SUMS、输入锁定清单、软件包清单和构建日志。
6. 完成离线检查，并重新烧写、冷启动、GPU 和视频验收；保留未通过项目。
7. 将唯一入口、全部必要输入与验收证据上传，随后才宣称“全新主机一键复现已通过”。

这里的系统等价不等于磁盘镜像逐字节相同：当前打包器没有固定 ext4 的全部随机量和时间字段。若要求镜像 SHA-256 也完全一致，需另做确定性文件系统打包和两次独立构建对照，不能沿用功能验收结论。

## 备份校验

四个仓库均附 `SOURCE-MANIFEST.json`。直接校验提交对象，可以避免 Windows 换行转换掩盖缺失或损坏的文件：

```sh
python3 tools/verify_source_manifest.py . --git-ref HEAD
```

捕获日志保留原始字节，源码文本采用 LF。验收数据中的历史限制仍然有效：无线、物理音频、Chromium Cedar 和严格视频零丢帧尚未通过，不能在复现镜像里标为已解决。
